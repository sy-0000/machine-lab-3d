## 共用技術架構

- **入口**：所有裝置開同一個首頁；只有 `navigator.xr.isSessionSupported('immersive-vr')` 為 true 時，首頁顯示「進入 VR」。桌機維持原本所有頁面與 HTML 按鈕，不加 3D 世界入口。
  - 按下「進入 VR」時在同一次點擊中開 XR session（瀏覽器要求使用者手勢），再切到 `#/world`，世界建好後接手 session（`src/components/VrEntryButton.jsx`）。
  - `#/world` 給 Quest 用，但桌機可直接輸入網址開啟（滑鼠繞看、F 開關 FPS），方便用 Immersive Web Emulator 除錯。
  - `#/world` 與 `src/xr/` 全部動態載入（React.lazy / import()），不增加原本頁面的載入量。
  - 離開 VR 後回到首頁。
- **單一 WebGLRenderer**（vanilla three.js，`xr.enabled`，`local-floor`），`src/xr/world.js`。XR 中略過後製（EffectComposer）；桌機開 `#/world` 時保留後製。
- **SceneManager**：大門口與工作室為獨立場景模組，提供 `enter()` / `exit()` / `update(dt)`；`exit` 時 dispose 幾何、材質、貼圖；切換時淡出淡入。
- **InputManager**：滑鼠點擊與控制器 trigger → `hover` / `select`；控制器 grip → `grab` / `drag` / `release`。各區域只聽這些事件。兩手控制器都顯示射線，hover 時物件高亮。不支援手部追蹤，但架構保留擴充空間。
- **3D UI**：CanvasTexture 面板；繁中字型在建置時依 data 檔與 UI 字串產生子集 woff2。面板距離使用者約 1–1.5 m，字要大到在頭盔中清楚可讀。桌機沿用 HTML 介面。
- **工安規則**在 `src/data/safety-rules.json`（從原 SafetyPage 原樣抽出，文字不改；每條是文字片段陣列，`strong: true` 為粗體）。桌機 `SafetyPage` 改讀這份，改前改後的頁面 HTML 逐字相同。
- **VR 不自動移動視角**：VR 中程式不可自行移動或旋轉視角；所有「鏡頭移動」一律「淡出 → 固定站位 → 淡入」（`SceneManager.moveTo`）。桌機 `#/world`（除錯）可以平滑移動鏡頭。
- **點光源**：每個場景 6 盞以內（大門口目前 4 盞：門外 2 盞煤氣燈、玄關 2 盞吊燈；室內點光源不開陰影）。
- **HTTPS 開發**：`npm run dev:xr`（`@vitejs/plugin-basic-ssl`，`--mode xr`）；`npm run dev`、建置與 Playwright 仍是 HTTP。
- **FPS 顯示**：可開關（桌機 F、VR 右手 B；開發模式預設開、正式版加 `?fps` 開）。先不做額外效能優化，Quest 實機低於 72 fps 再處理。
- **機台朝向**：VR 中房間固定、機台正面朝南（+Z，朝大門與工作桌），`VR_FACING = { lathe: 0, milling: −90°, drill: 0 }`；桌機版維持原本「轉房間」的方式。鑽床站在 0.72 m 鐵座上（與桌機相同）。

## VR 操作介面（第 6 階段起實作）

### 原則

- VR 中以「直接操作機台」為主，取代桌機的軸向選擇與 −／＋ 微調按鈕。
- 機台旁固定一塊儀表板，顯示狀態並提供少量按鈕。
- 桌機 ControlPanel（進階控制）的滑桿與行程設定，VR 不實作。

### 1. 直接在機台上操作

- 手輪：grip 抓住畫圈轉動（見上）。
- 主軸開關、車床正反轉撥桿、腳踏煞車、轉速段位旋鈕、HIGH／LOW、刀座分度：射線指向後按 trigger 觸發，沿用桌機場景中可點擊的邏輯（`MachineModel.jsx` 的 wheel／lever／detent／index／emergency／toggle 分類）。
- 銑床、鑽床的轉速：在儀表板上調整。

### 2. 機台旁儀表板

- 黃銅外框、玻璃錶面的蒸汽龐克風格立式儀表板，固定立在操作位旁邊，高度約在使用者胸口，面向操作位瞬移點。
- 每台機台各自一塊，固定在鋼板上，跟著機台一起翻轉。
- 位置不能擋住手輪與使用者的視線。**擺放建議（待確認）**：三台都放在鋼板左前角，錶面約 0.5 × 0.4 m、上緣高約 1.3 m、向後傾 30°，轉向正面瞬移點（距離約 1.0 m）。

  | 機台 | 儀表板中心（鋼板座標） | 理由 |
  |---|---|---|
  | 車床 | (−0.95, 0.65) | 主軸箱前方偏外側；正面手輪隨溜板在 x −0.14～+0.38 移動、尾座手輪在右端，都不受影響；從正面與左側瞬移點伸手到主軸箱旋鈕的路線不經過儀表板 |
  | 銑床 | (−0.95, 0.70) | X 軸左手輪在 (−0.71, 0.40)，工作臺左移到底時手輪到 x≈−1.11，但 z 相差 0.3 m 以上，不會撞到；不擋正面的 Y／Z 手輪 |
  | 鑽床 | (−0.60, 0.55) | 進給手柄在右前方，左前方空著 |

**第一頁：加工中（常駐顯示）**

- 顯示：DRO 座標讀值（各軸）；接觸狀態（未接觸／接觸／切削中／壓入）用顏色燈號；轉速；車床的目前長度、刀尖處直徑；過頭、危險區、錯誤訊息。
- 按鈕：每格進給量 0.01／0.1／1 mm（分段切換）；各軸歸零；刀具選擇（銑床、鑽床，停機時才能換）；銑床、鑽床轉速 −／＋；放上工件／換新毛胚、卸下工件；「設定」→ 第二頁。

**第二頁：設定**

- 車床：加工模式（外徑／端面）、小刀架角度、錐度靠模（開關＋角度）、移動到工件座標 X／Z、清除工件座標。
- 鑽床：深度擋塊（開關＋深度）。
- 全部：重設操作。
- 數字輸入用 −／＋ 按鈕調整（按住連續加減），不使用虛擬鍵盤。
- 「返回」→ 第一頁。

### 3. 每格進給量與手輪的關係

- 手輪每轉過一個刻度，軸移動「每格進給量」設定的距離，而不是依真實手輪比例（0.01 mm 精修、1 mm 快速移動）。
- 刻度間距每 10°（可在設定檔調整）。
- 每過一格：控制器輕震＋手輪喀一聲；DRO 同步更新。
- 碰到行程上下限：較強震動＋金屬碰撞聲，手輪轉不過去。
- 鑽床進給手柄維持 −115°～0° 與放開回彈，不套用每格進給量。

### 4. 加工回饋

- 切削中：控制器持續輕微震動，強度隨切削量增加。
- 沿用桌機的切削音效，VR 中改為從機台位置發出的 3D 空間音效。
- 刀尖壓入（進給過深）時：較強震動＋警告燈號＋警告聲。

## 工件存檔（第 8 階段）

- 存檔對象是「工件」，不是整個工作室；三格存檔（localStorage，新 key，例如 `machine-lab:vr-saves`，不碰桌機原本的工件存檔）。任一台機台加工後的工件都可以存進任一格。VR 不做限時關卡。
- 左手選單「存檔／讀取」：
  - 存檔：把目前機台上的工件存進選擇的格子；格子已有工件時先確認是否覆蓋。
  - 讀取：選擇一格，把工件裝到目前機台上。
  - 每格顯示：工件來源機台、存檔時間、工件縮圖（CanvasTexture 渲染小圖）。
- 讀取限制：車床工件只能讀回車床；銑床與鑽床共用高度場格式，可以互相讀取；不相容時讀取按鈕不可用，並提示要切換到哪台機台。
- 格式：

  ```js
  { version: 1, slots: [slot, slot, slot] }
  // slot = null 或
  { savedAt, sourceMachine, format: 'lathe-profile' | 'heightfield',
    workpiece: { state, mount: { fixture, orientation } }, extra: {} }
  ```

- 版本號要能支援之後改成六面高度場時的資料轉換（依版本號逐版遷移）。
- 跨機台裝夾（例如車床工件拿到鑽床加工）之後可能會做，格式預留空間，現在不實作。

## 工件取下與重新裝夾（第 9 階段）

- 主軸停止時才能用 grip 抓住工件取下；拿在手上可自由轉動檢視。
- 裝回時靠近夾頭或虎鉗出現半透明預覽，依手部方向吸附到最接近的有效朝向，放開 grip 即裝上。
- 有效朝向：**車床「正向／調頭」**（半徑陣列反轉、Z 鏡像）；**虎鉗「繞垂直軸每 90°」**（網格轉置／翻轉、長寬互換、孔座標跟著轉，虎鉗依新尺寸重建）。不需修改切削程式，新增轉換函式與 `workpiece.reclamp` 指令。
- 工件資料結構：車床 `WorkpieceState.js`（沿 Z 每 0.5 mm 一個半徑值＋夾持範圍）；銑床、鑽床 `HeadWorkpieceState.js`（長×寬網格的頂面高度＋孔清單）。

## 六面高度場（第 11 階段，已評估可行）

- 工件六個面各一張「從該面往內的切削深度」網格；每次裝夾只從上方加工，只修改當時朝上那一面；工件形狀＝六面保留區的交集（只由上往下切、沒有倒勾時是精確表示）。孔清單加上方向；朝向共 24 種（6 面朝上 × 4 個水平角度）；舊資料可轉換（原頂面 → +Z 面，其餘五面未切）。
- 網格：6 張位移網格＋片段著色器用其餘五張高度場貼圖裁切（約 6–9 萬三角形，切削時只局部更新，每格 < 1 ms）；陰影用相同裁切的 depth material。不用體素＋marching cubes（每次重建 50–150 ms）。
- 影響：接觸偵測改查交集後的實際頂面；關卡評分改用查詢介面，評分邏輯不變；屆時再決定桌機是否一起換格式。
- 工作量：約第 6、7 階段總和的 1.5 倍（資料結構與轉換、任意朝上面切削、網格與 shader、虎鉗／評分／桌機回歸、24 種朝向吸附）。

## 測試注意事項

- 跑 Playwright 的規則：
  1. 一律無頭模式（headless），不開出瀏覽器視窗。
  2. 一律 `--workers=1`，一次只跑一個測試。
  3. 跑之前先關掉自己開的預覽／開發伺服器；結束後確認沒有殘留的 node 或瀏覽器程序。
  4. 跑全套測試前先告訴需求方。
- 原因：兩個 Vite 伺服器（預覽 5173 與 Playwright 5220）同時跑會共用 `node_modules/.vite` 依賴快取、互相觸發重新整理，造成大量誤判失敗；瀏覽器測試也會讓電腦變慢。
- 基準：見下方「Playwright 基準」。
